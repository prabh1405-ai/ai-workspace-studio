# DOLPHIN AI STUDIO
## An Intelligent Natural Language Database Engineering and SQL Learning Workspace

# CHAPTER 1
# INTRODUCTION

## 1.1 Introduction and Project Background

Databases are an important part of modern software applications. Websites, mobile applications, hospitals, banking systems, educational platforms and business applications use databases to store and manage information. SQL (Structured Query Language) is commonly used to create database structures, retrieve information, update records and manage relationships between tables.

However, working with databases requires knowledge of SQL syntax, table structures, primary keys, foreign keys, joins and database design. Beginners and non-technical users often find it difficult to convert their requirements into correct SQL statements. Even experienced developers spend time writing queries, designing database schemas and correcting structural errors.

Recent developments in Artificial Intelligence and Large Language Models have made it possible to understand natural language and generate structured code. Natural Language to SQL systems allow users to describe their data requirements in simple English and receive corresponding SQL queries.

Dolphin AI Studio is proposed as an intelligent database workspace that combines natural language SQL generation, AI-powered explanations, database design, conversational modification and SQL learning. Users can interact with the system through a familiar database development interface without depending entirely on manual SQL coding.

The platform also introduces an AI Database Designer that converts business requirements into complete database structures. It analyzes entities, relationships and constraints, identifies missing requirements and generates SQL scripts with visual ER diagrams.

## 1.2 Problem Statement

Traditional database development requires users to have sufficient knowledge of SQL and relational database concepts. Converting business requirements into database structures and SQL queries can be difficult for beginners and time-consuming for developers.

Existing AI-based query generation tools can generate SQL from natural language, but users may still face problems understanding the generated queries, validating database structures and managing changes to existing schemas.

The major problems include:

- Difficulty in converting natural language into correct SQL queries.
- Lack of SQL knowledge among non-technical users.
- Difficulty in designing complete database structures from business requirements.
- Missing or unclear relationships between database tables.
- Limited understanding of generated SQL statements.
- Manual creation of ER diagrams and database documentation.
- Difficulty in identifying missing or ambiguous database requirements.
- Repeated database modifications requiring manual SQL changes.
- Limited integration between SQL learning and database development.

Therefore, there is a need for an integrated intelligent workspace that simplifies SQL generation, database design, validation, visualization and learning through natural language interaction.

## 1.3 Motivation and Need for the Project

The main motivation for developing Dolphin AI Studio is to reduce the gap between human language and database development.

Many people understand what information they need from a database but do not know how to express their requirements using SQL. Similarly, developers may understand the business requirements of an application but need time to convert them into a complete relational database structure.

The project is motivated by the following requirements:

- To make database operations accessible to non-technical users.
- To reduce the time required for writing SQL queries.
- To help students understand SQL through simple explanations.
- To generate complete database structures from business requirements.
- To identify missing information before generating database schemas.
- To provide automatic validation of generated database structures.
- To simplify database modifications through conversational instructions.
- To provide a single workspace for database learning and development.

## 1.4 Aim and Objectives

**Aim**

To develop an AI-powered natural language database engineering workspace that converts user requirements into SQL queries and complete database structures while providing explanations, validation, visualization and interactive SQL learning.

**Objectives**

- To develop a natural language interface for generating SQL queries.
- To generate SQL statements from English and supported language inputs.
- To provide simple explanations for generated SQL queries.
- To develop an interactive SQL practice environment.
- To create complete database schemas from business requirements.
- To identify entities, attributes, relationships and constraints.
- To detect missing and ambiguous database requirements.
- To generate a structured database blueprint before SQL generation.
- To validate generated database structures.
- To automatically generate Entity Relationship Diagrams.
- To support conversational database modifications.
- To maintain database versions and generate incremental SQL changes.
- To provide SQL scripts and database documentation for export.

## 1.5 Scope of the Project

The project focuses on developing an integrated AI-based SQL workspace for database query generation, database design and SQL learning.

The system covers two major working environments: Query Workspace and AI Database Designer.

The Query Workspace allows users to enter natural language questions and generate corresponding SQL statements. It also provides query explanations, voice input, multilingual support and an interactive practice environment.

The AI Database Designer allows users to describe complete application requirements, such as an e-commerce, hospital or student management system. The system analyzes the requirements, identifies entities and relationships, creates a structured database blueprint and generates the corresponding SQL script.

The system also includes schema validation, ER diagram generation, conversational database modification, version management and export functionality.

The initial implementation focuses on relational database systems such as MySQL and PostgreSQL. Advanced enterprise database administration, unrestricted production database modification and support for every database technology are outside the initial scope.

# LITERATURE REVIEW

## 2.1 Introduction

This chapter reviews research related to Natural Language to SQL generation, Large Language Models, database schema understanding, SQL validation and conversational database interfaces.

Artificial Intelligence has introduced new methods for converting human language into structured database queries. However, generating accurate SQL requires understanding the user's intention, identifying the correct database tables and columns, understanding relationships and producing syntactically valid queries.

The reviewed research provides the technical foundation for developing Dolphin AI Studio and helps identify the limitations that the proposed system aims to address.

## 2.2 Review of Relevant Research Papers

**1. PICARD: Parsing Incrementally for Constrained Auto-Regressive Decoding from Language Models (2021)**

Torsten Scholak, Nathan Schucher and Dzmitry Bahdanau introduced PICARD, a method that improves SQL generation by checking generated tokens during the decoding process. It prevents invalid SQL sequences by rejecting tokens that do not satisfy parsing constraints.

This research demonstrates the importance of controlling generated SQL output and reducing syntax errors. Dolphin AI Studio uses the same general motivation for including a separate SQL validation stage, although its implementation and validation approach must be developed independently. [1]

**2. DIN-SQL: Decomposed In-Context Learning of Text-to-SQL with Self-Correction (2023)**

Mohammadreza Pourreza and Davood Rafiei proposed a method that divides Text-to-SQL generation into smaller reasoning tasks. Instead of generating the complete SQL query in one step, the system uses multiple stages and self-correction.

This research supports the idea of separating user-intent understanding, schema identification and SQL generation into individual processing stages. [2]

**3. A Survey of NL2SQL with Large Language Models: Where Are We, and Where Are We Going? (2024)**

Xinyu Liu and other researchers reviewed the use of Large Language Models for converting natural language into SQL.

The study discusses schema linking, natural language ambiguity, database information, evaluation methods and error analysis. It identifies the importance of understanding database structures before generating queries.

This research provides a foundation for the schema-aware processing approach proposed in Dolphin AI Studio. [3]

**4. Next-Generation Database Interfaces: A Survey of LLM-Based Text-to-SQL (2024)**

Zijin Hong and other researchers studied the development of database interfaces using Large Language Models.

The research discusses challenges involving complex database schemas, natural language understanding, query generation and evaluation.

It supports the need for intelligent database interfaces that help users interact with databases without requiring extensive SQL knowledge. [4]

**5. Representing Schema Structure with Graph Neural Networks for Text-to-SQL Parsing (2019)**

Ben Bogin, Matt Gardner and Jonathan Berant studied how database schema relationships can improve natural language to SQL parsing.

Their work demonstrates that relationships between tables and columns are important when generating queries across complex databases.

This research supports the use of database relationship information and ER-based representations in Dolphin AI Studio. [5]

## 2.4 Research Gap

Existing research has made significant progress in natural language SQL generation and schema-aware query processing. However, database development involves more than converting a question into an SQL statement.

Several practical requirements remain important:

- Users need assistance in converting incomplete business requirements into structured database designs.
- Ambiguous relationships should be identified before generating database structures.
- Generated schemas require structural and relational validation.
- Users need to understand why particular tables and relationships are created.
- Existing database structures need controlled modifications when requirements change.
- SQL learning and professional database development can be combined within one workspace.

Dolphin AI Studio addresses these requirements through an integrated workflow involving requirement analysis, database blueprint generation, validation, SQL generation, visualization and conversational modification.

The proposed system focuses on combining these capabilities rather than treating SQL generation as an isolated operation.

## 2.5 Existing System and Its Limitations

Existing database development tools and AI assistants provide different capabilities.

Examples include ChatGPT, Google Gemini, Microsoft Copilot, MySQL Workbench and other Text-to-SQL solutions.

**Common capabilities of existing systems:**

- Natural language to SQL generation.
- SQL syntax assistance.
- Database query execution.
- Database table management.
- AI-based code explanations.
- Database visualization through separate tools.

**Limitations addressed by the proposed project:**

- Users may need separate tools for query generation, schema design and visualization.
- Generated SQL may require manual validation.
- Incomplete requirements may produce unsuitable database structures.
- Database changes may require manually identifying affected tables.
- Learning and database development are often handled through separate workflows.
- Users may need to manually maintain documentation and schema versions.

## 3.1 Overview of the Proposed System

Dolphin AI Studio is an AI-powered database workspace designed to simplify SQL development and database design through natural language interaction.

The system provides users with a familiar database development environment combined with AI-powered assistance.

The application consists of two primary working environments.

**1. Query Workspace**

This environment allows users to enter questions in natural language and receive SQL queries. The generated queries are displayed in an SQL editor, while an explanation panel describes the SQL logic.

**2. AI Database Designer**

This environment allows users to describe complete application requirements. The AI analyzes the requirements, identifies entities, attributes and relationships, generates a structured database blueprint, validates the design and produces a complete SQL script.

Additional features include Practice Mode, multilingual input, automatic ER diagram generation, conversational database modification, history and export.

**AI Database Designer**

Users can describe a complete application requirement, and the system generates a relational database structure.

## 4.1 Overall Methodology and Workflow

The system follows a multi-stage workflow to convert user requirements into SQL queries or complete database structures.

The process begins with user input through the Query Workspace or AI Database Designer.

For query generation, the system analyzes the user's question, identifies the database intent and generates the corresponding SQL statement.

For database design, the system analyzes the business requirements, identifies entities and relationships, checks for missing information and generates a structured database blueprint.

The generated output passes through validation before being displayed to the user.

The application is divided into the following modules.

Accepts user requirements through text or supported voice input.

**2. Query Generation Module**

**3. SQL Explanation Module**

**4. Practice Module**

Generates visual database relationship diagrams.

Maintains database design versions and records modifications.

**12. Export Module**

Generates SQL scripts, ER diagrams and database documentation.

## 4.3 Algorithm and Technique Description

### 4.3.1 Natural Language Understanding

The system receives a natural language request and processes it using an AI language model.

The processing stage identifies the action requested by the user, such as retrieving information, inserting records, updating data or creating a database.

The extracted information is converted into a structured representation that can be used by the next processing stage.

### 4.3.2 Intent Detection

The system identifies whether the user requires:

- SQL query generation.
- SQL explanation.
- Database creation.
- Schema modification.
- SQL practice.
- Database information.

Based on the detected intent, the request is forwarded to the appropriate module.

### 4.3.3 Database Entity and Relationship Extraction

For database design, the system identifies entities, attributes and relationships from the user's requirements.

Example:

User requirement:

"Create an e-commerce database with customers, products and orders."

Extracted entities:

- Customer
- Product
- Order

Possible relationships:

- One customer can place multiple orders.
- One order can contain multiple products.
- One product can appear in multiple orders.

A junction table such as Order_Items is required to represent the many-to-many relationship between orders and products.

### 4.3.4 Requirement Completeness and Ambiguity Detection

The system checks whether the user's requirements provide enough information to create a meaningful database structure.

For example, if a user requests an employee database with departments, the system may ask whether an employee can belong to one department or multiple departments.

The system uses the answer to complete the database blueprint before generating the SQL structure.

### 4.3.5 Database Blueprint Generation

The system converts the extracted requirements into an intermediate database representation.

The blueprint contains:

- Entity names.
- Attribute names.
- Data types.
- Primary keys.
- Foreign keys.
- Relationships.
- Constraints.
- Business rules.

This representation separates database understanding from final SQL generation.

### 4.3.6 SQL Generation

The structured database blueprint is passed to the SQL generation module.

The system generates the required SQL statements, including:

- CREATE DATABASE.
- CREATE TABLE.
- PRIMARY KEY.
- FOREIGN KEY.
- UNIQUE constraints.
- NOT NULL constraints.
- INDEX creation.
- INSERT statements.

The generated script follows the selected database dialect.

### 4.3.7 Schema Validation and Repair

The generated schema is checked for structural and relational problems.

The validation process includes:

- Missing primary keys.
- Invalid foreign key references.
- Data-type mismatches.
- Duplicate entity definitions.
- Missing junction tables.
- Invalid relationship definitions.
- Constraint conflicts.
- SQL syntax errors.

If an error is identified, the system can attempt a correction and validate the revised output again.

### 4.3.8 Conversational Schema Modification

The system maintains the current database design as context for follow-up requests.

For example:

Initial requirement:

"Create an e-commerce database."

Additional requirement:

"Add a subscription system."

The system identifies the affected entities and generates the required database changes without unnecessarily recreating the complete schema.

### 4.3.9 Database Version Management

Every approved modification can create a new database design version.

The system maintains the previous and updated structures to help users review changes and understand the evolution of their database.

### 4.3.10 SQL Explanation and Practice Evaluation

The explanation module describes generated SQL in simple language.

The practice module evaluates user-written SQL using syntax checks, expected query results and logical comparison where applicable.

Feedback is provided to help users identify and correct errors.

## 4.4 Dataset and Data Preprocessing

The proposed system uses natural language requirements and relational database schemas as its primary inputs.

Unlike conventional supervised machine learning projects, the initial implementation can use an existing Large Language Model through an API rather than training a new language model from scratch.

The input data includes:

- Natural language database questions.
- Application development requirements.
- Database table definitions.
- Column names and data types.
- Primary and foreign key information.
- SQL practice questions.
- Expected query outputs.

The preprocessing stage involves:

- Removing unnecessary input formatting.
- Identifying important entities and keywords.
- Extracting database actions.
- Identifying relationships and constraints.
- Structuring requirements into machine-readable data.
- Validating the generated blueprint before SQL generation.

For evaluation, test requirements can be prepared for different domains, including e-commerce, hospital management, student management and inventory management.

## 4.5 System Design

The system follows a modular design in which frontend components communicate with backend services through APIs.

The frontend provides separate interfaces for query generation, database design, SQL explanation, practice and history.

The backend processes requests and communicates with the AI model, validation services and database systems.

The database blueprint acts as an intermediate representation between natural language requirements and final SQL generation.

This approach helps separate requirement understanding, database design and SQL generation.

The generated schema is used to create the ER diagram and supporting documentation.

## 5.5 Challenges Encountered and Corrective Measures

### 5.5.1 Natural Language Understanding

**Challenges**

- Users may describe the same requirement in different ways.
- Some questions may contain incomplete information.
- Business requirements may include multiple database operations.

**Corrective measures**

- Use structured prompt processing.
- Separate intent detection from SQL generation.
- Use requirement clarification when necessary.
- Maintain context for follow-up requests.

### 5.5.2 Database Schema Generation

**Challenges**

- Complex requirements may contain multiple entities.
- Relationships may be unclear.
- Incorrect data types and constraints can affect database consistency.

**Corrective measures**

- Generate a structured database blueprint.
- Identify entities and relationships before generating SQL.
- Apply primary key and foreign key checks.
- Validate the generated schema.

### 5.5.3 SQL Generation and Validation

**Challenges**

- AI-generated queries may contain syntax errors.
- Different database platforms use different SQL dialects.
- Queries may reference unavailable tables or columns.

**Corrective measures**

- Use dialect-specific generation instructions.
- Validate generated SQL using a SQL parser.
- Check generated queries against database metadata.
- Provide corrective feedback when errors are identified.

### 5.5.4 Conversational Database Modification

**Challenges**

- Follow-up instructions may affect existing tables.
- Repeated modifications may create conflicting structures.
- The system must preserve existing relationships.

**Corrective measures**

- Maintain the current database blueprint.
- Identify affected entities before generating changes.
- Generate incremental migration scripts.
- Maintain schema versions for review.

### 5.5.5 Frontend and Backend Integration

**Challenges**

- Multiple AI modules must communicate with the same backend.
- Large SQL outputs require proper editor handling.
- The application must display errors and results clearly.

**Corrective measures**

- Use modular FastAPI endpoints.
- Maintain structured API responses.
- Separate AI processing from frontend presentation.
- Use a consistent database workspace layout.

# CHAPTER 7
# CONCLUSION AND FUTURE WORK

## 7.1 Summary of Project Work

Dolphin AI Studio is proposed as an integrated AI-powered database engineering and SQL learning workspace.

The project focuses on reducing the difficulty of database development by allowing users to communicate with databases through natural language.

The Query Workspace generates SQL queries and provides explanations to help users understand database operations. The Practice Mode provides an environment for students to improve their SQL knowledge.

The AI Database Designer extends the functionality by converting business requirements into complete database structures. It analyzes entities, attributes, relationships and constraints before generating SQL scripts.

The system also includes requirement completeness analysis, schema validation, automatic ER diagram generation, conversational database modification and version management.

## 7.2 Conclusion

Dolphin AI Studio aims to simplify database development by combining Artificial Intelligence, Natural Language Processing and Database Management within a single workspace.

Traditional database tools require users to manually understand and write SQL statements. The proposed system reduces this difficulty by allowing users to express their requirements in simple language and receive structured SQL output with explanations.

The AI Database Designer provides an additional capability by generating complete database structures from application requirements. By introducing requirement analysis, database blueprint generation and schema validation, the system aims to improve the quality of automatically generated database designs.

Conversational modification allows users to extend existing database structures without manually rewriting the complete schema. Automatic ER diagram generation and documentation export further simplify database development.

The project aims to provide a practical environment for students, developers and non-technical users to learn SQL, generate queries and design relational databases more efficiently.

## 7.3 Planned Enhancements and Future Work

**Advanced Database Support**

Future versions can support additional database platforms such as SQLite, Oracle and Microsoft SQL Server.

**Advanced Query Optimization**

The system can provide suggestions for improving query performance through indexing recommendations and query analysis.

**Advanced Database Migration**

The system can generate migration scripts for modifying existing databases while maintaining data consistency.

**Database Performance Analysis**

Future development can include query execution analysis, performance monitoring and database optimization recommendations.

**Team Collaboration**

Multiple users can collaborate on database designs and review schema changes.

**Advanced Security**

**Local AI Model Support**

The system can support locally hosted language models to improve privacy and reduce dependence on external AI services.

**Cloud Deployment**
